# Data source and redistribution notice

The repository can contain data retrieved from ChEMBL, BindingDB, and PubChem BioAssay. “Publicly accessible” does not mean “public domain,” and this repository does not relicense upstream content.

## Responsibilities by source

- **ChEMBL:** review the current [ChEMBL data license](https://chembl.gitbook.io/chembl-interface-documentation/about), [release DOI table](https://chembl.gitbook.io/chembl-interface-documentation/downloads), and [EMBL-EBI terms of use](https://www.ebi.ac.uk/about/terms-of-use/). Preserve ChEMBL attribution, release/status, and any share-alike obligations that apply to redistributed derivative data.
- **BindingDB:** review the [BindingDB information and references](https://www.bindingdb.org/rwd/bind/info.jsp). BindingDB distinguishes staff-curated data from ChEMBL-imported data with different Creative Commons terms. Preserve original provenance rather than treating the whole export as one rights category.
- **PubChem BioAssay:** follow the [PubChem citation guidelines](https://pubchem.ncbi.nlm.nih.gov/docs/citation-guidelines) and identify important AIDs/depositors. PubChem aggregates contributed records; check original depositor/source terms for the intended redistribution.
- **Literature and patents:** database indexing does not grant rights to reproduce full articles, figures, protocols, or protected patent content, and does not remove patent or other intellectual-property rights.

The detailed resource citations are in [external sources](external_sources.md).

## Before releasing data or models

For the exact frozen build:

1. Inventory every raw and processed file and its contributing source/provenance.
2. Verify raw, processed, software, models, analysis, and reports manifests plus their build/upstream/direct-input links when analysis is enabled.
3. Decide whether raw files should be redistributed or regenerated by users.
4. Check whether processed tables constitute an adapted database and which attribution/share-alike terms apply.
5. Include source citations, release/status, access date, target/query, and record-selection rules.
6. Review model artifacts, predictions, chemical-intelligence tables, reference coverage, and proposed experiment selections for data-license and disclosure implications.
7. Obtain the rights holder's repository license decision; the repository currently has no software license.

A trained model is not automatically exempt from upstream data terms. Its release also requires a scientific and security review.

## Proprietary and collaborator data

No Wang lab, mentor, collaborator, sponsor, or other non-public data should enter a public commit or release without explicit data-owner approval. Structures and assay results may reveal unpublished intellectual property even when compound IDs are pseudonymous.

Keep private inputs and every derivative—curated tables, plots, nearest neighbors, logs, caches, manifests, split assignments, and model files—in approved access-controlled storage. Follow [the proprietary-data intake protocol](proprietary_data_intake.md).

## Data availability statement template

Adapt this to the actual approved release:

> Public bioactivity records were retrieved from ChEMBL, BindingDB, and PubChem BioAssay using the target identifiers and queries reported in the methods. The analyzed public snapshot and derived software/model/analysis/report bundle are identified by the linked raw, processed, software, models, analysis, and reports SHA-256 manifests in [archive/release]. Source-specific access and redistribution terms apply. [If applicable:] Proprietary experimental data are not publicly distributed because of [approved concise reason]; access requests are reviewed by [data steward/process], and approved aggregate validation outputs are provided in [location].

Do not promise access to private data unless the data owner has approved a real request procedure.
